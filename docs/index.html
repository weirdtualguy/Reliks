Generative art on Kaspa

The artwork is a program. Its hash lives in the contract.

Reliks anchors a small deterministic engine inside a Kaspa covenant. Anyone can re-render every edition from public chain data. This page does exactly that in your browser, and withholds the art if any check fails.

Protocol
What Reliks is, and what it is not.


Reliks is three Silverscript covenants and a set of tools. It is not a marketplace, an indexer or an audited product. This page keeps the claims small enough to check.


Claims


ClaimStatusBasis


The image is a function of (engine, serial)Checked in pageEngine hash, image hash and serial are recomputed on load.


The engine cannot be swapped after mintContractprogram_hash is part of covenant state and of every successor's script.


Serials never collide across parallel lanesContractSerial is derived from the consumed lane outpoint; the page recomputes it.


No protocol feeContractPrimary sale pays the artist exactly the price. Network fees (about 0.04 KAS per mint) still apply.


Royalties on resaleContract, partlyEnforced on covenant-priced sales (list/buy, escrow accept). transfer and zero-price sell are royalty-free by design.


The art survives pruningNot claimedThe hash is anchored on chain and the engine bytes ship in the contract script, but pruned nodes may drop old transactions. Keep a copy of the engine (this repository has one).

Wallet

Kaspire Extension
Injected window.kaspire provider. No relay, no QR, no third-party script. It signs the mint's wallet input and broadcasts with pushTx.

Kaspire Mobile
WalletConnect v2, loaded only when you choose it. It can connect and sign. Covenant transactions cannot be broadcast through public REST, so paste your own node address, or use the extension.

Test small
The wallet flow follows Kaspire's published API and is tested against mocks. Try it first on a series with editions left, with a low-value wallet.




How a mint works


    

  1. The page rebuilds the live lane state from public chain data and proves it recomputes to the on-chain script.
    2. 

  2. It builds one transaction: the lane advances by one, a new edition covenant is created with a 1 KAS carrier, and the artist is paid the price.
    3. 

  3. Kaspire shows its own review of that exact transaction and signs only your funding input.
    4. 

  4. The page checks that the signed transaction still matches what you reviewed, and only then broadcasts.
